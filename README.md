# Laser-beam perturbation: numerical reproducibility materials

Companion computational materials for the manuscript:

**Can Non-Gaussian Residuals Enable Remote Detection of a Laser Beam Perturbation along Its Propagation Path?**

Submitted to *Royal Society Open Science* (manuscript reference: RSOS-262349).

## 1. Scientific scope

This repository supports a **numerical proof of principle**, not a completed laboratory demonstration. It investigates whether deviations from a Gaussian transverse laser-beam intensity profile, together with non-Gaussian residual statistics and spatial correlation measures, can reveal a localized phase perturbation along the propagation path.

The model propagates a coherent Gaussian beam using an FFT-based Fresnel calculation. A spatially correlated, thermally inspired phase screen represents the perturbation. Independent stochastic realizations are analyzed to characterize the distribution and repeatability of numerical observables.

**Figure 1** in the manuscript is a conceptual diagram of a proposed experimental arrangement and is not generated by this notebook. **Figures 2–4** are numerical results generated by the notebook.

## 2. Quick Start: Source Code and Reproducibility

The complete numerical implementation is available directly in this GitHub repository in two complementary formats:

- **Python source code:** [`code/rsos_Laser_Study_Consolidated.py`](code/rsos_Laser_Study_Consolidated.py) — for direct inspection of the computational algorithms, numerical methods, and statistical analysis.
- **Jupyter Notebook:** [`code/RSOS_Laser_Study_Consolidated.ipynb`](code/RSOS_Laser_Study_Consolidated.ipynb) — for interactive execution and reproduction of the numerical results.

### Running the simulation

1. Open the Jupyter Notebook directly from this repository.
2. Download the notebook or open it in a compatible Jupyter environment.
3. Alternatively, run the notebook using [Google Colab](https://colab.research.google.com/) without requiring access to the authors' personal Google accounts.
4. Execute the notebook cells sequentially to reproduce the Monte Carlo simulations, statistical analyses, and publication figures.

The numerical source code, simulation outputs, and supplementary documentation are archived together to support transparency, independent inspection, and computational reproducibility.

5. Select a standard Python runtime. The implementation is intended for CPU execution; no GPU is required.
6. Select **Runtime → Run all** (or run the cells sequentially from top to bottom).
7. Allow approximately **11 minutes for the main simulation and statistical analysis**, based on the authors' observed Colab execution. The subsequent publication-figure cells typically complete much faster. Actual times depend on Colab resource allocation and software versions.
5. Download the resulting CSV files and the publication figures from the Colab Files panel, or use the packaging instructions supplied with the release.

The notebook runs the numerical simulation first and then renders the manuscript figure layouts. The standard Colab `sample_data/` directory is unrelated to this study and should not be included in the research archive.

## 3. Physical and numerical configuration

| Parameter | Value | Interpretation |
|---|---:|---|
| Grid size, `N` | 1024 × 1024 | Transverse numerical grid |
| Transverse domain, `Lx` | 80 mm | Simulation window |
| Gaussian-beam radius parameter, `w0` | 10 mm | Input beam scale |
| Wavelength | 532 nm | Optical wavelength |
| Propagation distance, `zprop` | 0.60 m | Distance to observation plane |
| `FILTER_SIGMA_PIXELS` | 18 pixels | Gaussian smoothing width of the stochastic phase texture |
| Physical width corresponding to filter | approximately 1.41 mm | Derived from the grid spacing; not an experimentally measured turbulence correlation length |
| Perturbation-envelope scale | 107 mm | Spatial envelope parameter; not the propagation distance |
| `N_REALIZATIONS` | 100 | Independent realizations per nonzero phase amplitude |
| `MASTER_SEED` | 2026 | Pseudorandom reproducibility seed |

The selected configuration followed preliminary parameter-exploration experiments and subsequent introduction of Monte Carlo sampling. It is **not claimed to be globally optimal or experimentally validated**. See Supplementary Information S1 for the development history, equations, interpretation, and limitations.

## 4. Numerical and statistical pipeline

1. Initialize the coherent Gaussian input beam and numerical grid.
2. Generate a spatially correlated stochastic phase perturbation for a selected phase amplitude.
3. Propagate the perturbed and reference fields using FFT-based Fresnel propagation.
4. Extract transverse intensity profiles, fit a Gaussian model, and compute residual observables.
5. Evaluate residual moments, candidate distribution fits (Gaussian, Student-t, generalized normal), AIC-based model comparisons, and spatial autocorrelation.
6. Repeat for the Monte Carlo ensemble and aggregate the statistics.
7. Export tabular outputs and manuscript Figures 2–4.

The computationally demanding portion is the ensemble simulation and statistical fitting, rather than figure rendering. FFT operations and repeated distribution fitting are plausible major contributors, but **no function-level timing profile has yet been published**; their relative runtime contributions should not be interpreted as measured benchmarks.

## 7. Software and reproducibility

The notebook requires Python 3 and the following packages:

- NumPy
- pandas
- SciPy
- Matplotlib

The fixed master seed enables repeatable pseudorandom sampling under a compatible software environment. Exact bitwise equivalence across library versions or computing platforms is not guaranteed. For archival reproducibility, record the package versions printed by the executed notebook and preserve the generated CSVs with the release.

Recommended validation before depositing a permanent Zenodo release: run the notebook from a clean Colab session; confirm the six CSV files and all three publication figures; compare the resulting numerical values and visualizations with the submitted manuscript; record the environment versions; and archive the outputs together with the source notebook.
